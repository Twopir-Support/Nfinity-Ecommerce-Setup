# 04 – UI: app, pages, LWC

Match `reference/ui-reference.html` screen by screen. Only one custom component:
`nftOrderLineStatus`. Everything else is standard Lightning components.

## 1. Layouts and compact layouts

| Object | Page layout | Compact layout (highlights) fields, in order |
|---|---|---|
| Order | `NFT Order Layout` | OrderNumber, `NFT_External_Order_Id__c`, `NFT_Channel__c`, `NFT_Fulfillment_Provider__c`, `NFT_Fulfillment_Status__c`, TotalAmount, AccountId, `NFT_Accounting_Status__c` → `NFT_Order_Compact` |
| Account | `NFT Account Layout` | Name, `NFT_Customer_Source__c`, `NFT_Rewards_Tier__c`, `NFT_Total_Orders__c`, `NFT_Open_Orders__c`, `NFT_Lifetime_Spend__c`, `NFT_Last_Order_Date__c` → `NFT_Account_Compact` |
| Product2 | `NFT Product Layout` | Name, ProductCode, Family, `NFT_Style__c`, `NFT_Colour__c`, `NFT_Size__c` → `NFT_Product_Compact` |
| `NFT_Shipment__c` | `NFT Shipment Layout` | Name, `NFT_Order__c`, `NFT_Carrier__c`, `NFT_Tracking_Number__c`, `NFT_Status__c` |
| `NFT_Invoice__c` | `NFT Invoice Layout` | Name, `NFT_Order__c`, `NFT_Amount__c`, `NFT_Status__c` |
| `NFT_Inventory_Balance__c` | `NFT Inventory Balance Layout` | Name, `NFT_Location__c`, `NFT_Qty_Available__c`, `NFT_Stock_Flag__c` |
| `NFT_Sync_Log__c` | `NFT Sync Log Layout` | Name, `NFT_System__c`, `NFT_Event__c`, `NFT_Status__c`, `NFT_Logged_At__c` |

Set each NFT compact layout as the object's primary compact layout. Page layouts carry
all NFT fields in a "Details" section. Do not change existing layouts' assignments;
assign the NFT layouts through the NFT pages and the permission set's app.

## 2. Path

`NFT_Order_Fulfillment_Path` on Order, field `NFT_Fulfillment_Status__c`, all record
types. Steps Received, Confirmed, Partially Shipped, Shipped, Delivered (Cancelled is
hidden: mark it as a "closed" value with no guidance). Key fields: Confirmed step →
`NFT_Confirmed_At__c`; Partially Shipped / Shipped → `NFT_First_Shipped_At__c`;
Delivered → `NFT_Delivered_At__c`. Celebration off.

## 5. LWC `nftOrderLineStatus`

Bundle `force-app/main/default/lwc/nftOrderLineStatus/` with `.html`, `.js`, `.css`,
`.js-meta.xml`, and `__tests__/nftOrderLineStatus.test.js` (Jest). Master label
"NFT Order Line Status". Target `lightning__RecordPage`, object Order only. No Apex.

Data (Lightning Data Service only):
- `getRecord` on Order: `NFT_Pct_Confirmed__c`, `NFT_Pct_Shipped__c`, `NFT_Pct_Invoiced__c`,
  `NFT_Total_Units__c`, `NFT_Units_Confirmed__c`, `NFT_Units_Shipped__c`, `NFT_Units_Invoiced__c`.
- `getRelatedListRecords` on `OrderItems`: `NFT_Line_No__c`, `Product2.ProductCode`,
  `Product2.Name`, `Product2Id`, `Quantity`, `NFT_Qty_Confirmed__c`, `NFT_Qty_Shipped__c`,
  `NFT_Qty_Invoiced__c`, `NFT_Line_Status__c`, `NFT_Short_Shipped__c`; sort by Line No.
- Refresh: include `LastModifiedDate` in the `getRecord` fields. When it changes (a
  quick action updated the order), call `refreshApex` on the related-list wire.

Layout (match screen 2 of the reference):
1. Card title "Line Items" with a small purple badge "Custom LWC · orderLineStatus".
2. Grey band with three white tiles: Confirmed / Shipped / Invoiced, each with the
   percentage (large, light weight), a 6 px progress bar (green, amber, blue) and
   "x of y units". The Shipped tile gets an amber bottom border when 0 < % < 100.
3. Filter pills: Total, Pending, Confirmed, Partially Shipped, Shipped, each with its
   count; one selected at a time (`aria-pressed`).
4. Table (`lightning-datatable` not used; plain SLDS table for the pills styling):
   #, SKU (link to the Product record via `NavigationMixin`), Description, Ordered,
   Confirmed, Shipped, Invoiced, Line status. Confirmed/Shipped/Invoiced cells are pills
   "x / y": green when x = y, amber when 0 < x < y, grey when 0. Rows with
   Short Shipped = true get background `#FEF6EC`.
5. If any line is short-shipped, a note under the table: "<units> unit(s) of <SKU> waiting
   for stock." with a link to that Product.
6. Loading state: `lightning-spinner`. Error state: an SLDS alert with the error text.
   Empty state: "No order lines yet."

Jest tests: renders tiles from mocked `getRecord`; renders 2 rows from mocked related
list; filter "Partially Shipped" shows 1 row; amber class on the short-shipped row.

## 6. App and utility bar

App `NFT_Commerce_Integration_Hub`, label "Commerce Integration Hub", Lightning,
standard navigation, brand colour `#0176D3`, description "NFT demo app".

Nav items, in order: `NFT_Operations_Home` (tab), standard-Order, standard-Product2,
`NFT_Inventory_Balance__c`, `NFT_Shipment__c`, standard-Account, `NFT_Sync_Log__c`,
`NFT_Invoice__c`, standard-report, standard-Dashboard.

Utility bar FlexiPage `NFT_Commerce_Hub_Utility_Bar` with three Flow utility items:
"Simulate Shopify Order" (F1), "Simulate Amazon / FBA Order" (F2), "Retry Failed Syncs"
(F7, all-failed mode). Width 420, height 560, icon `utility:flow`.

Action overrides in the app: Order View → `NFT_Order_Record_Page`; Product2 View →
`NFT_Product_Record_Page`; Account View → `NFT_Account_Record_Page` (form factor Large).

Visibility: assigned through permission set `NFT_Commerce_Hub_User` (and System
Administrator profile visibility so the running admin sees it).
